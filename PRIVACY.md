# Privacy

Reposco stores history locally and has no telemetry, account, sync, updater or crash-upload service. Reposco-owned code makes no network requests. History previews are plain text; copied URLs, HTML and Markdown are never fetched or rendered as resources.

First launch starts paused. Start / resume text capture is explicit consent to collect future Unicode text changes. The capture setting persists across launches, including Pause. Neither launch nor Resume imports the already-present clipboard. Pause rejects pending captures; an already-started storage transaction may finish. Capture filters never change or clear the clipboard. Explicit replay replaces it with the selected stored Unicode text; Ctrl+Enter copies only, while Enter/Shift+Enter request paste into the previous eligible application.

On launch Reposco creates or opens history.db and a versioned user-scope DPAPI key envelope, key.dat, under its Windows per-user application data location, even while capture is paused. A separate settings.ini stores capture/filter/retention preferences and native application exclusion paths, not clipboard text. Database content, comparison text and summaries stay in SQLCipher. Keys are randomly generated and transient key buffers are wiped. Key loss may make history unrecoverable; no recovery/export feature exists.

Known exclusion/ignore markers and local-history opt-out are screened before text access. Cloud-sync opt-out alone does not exclude local history. Native executable-path exclusions and default-on exact six-digit code exclusion are available. Optional exact eight-digit exclusion is off by default. Browser-extension provenance and arbitrary unmarked passwords cannot reliably be recognized. Do not enable capture while copying unmarked secrets. History uses 1000-item, 90-day and 1-GiB original payload limits. Canonical comparison text, metadata, encryption overhead and unused pages are additional disk usage; the physical database may remain larger after eviction. Confirmed Clear history in Settings/Tray pauses capture and deletes history logically, without promising forensic SSD erasure. Changing filters does not retroactively delete stored content.

Tests use synthetic data and temporary directories. Default tests never actively read or write the session clipboard; optional active native tests require a separate private window station and fail when isolation is unavailable. A separate explicitly coordinated interactive test mode uses only synthetic values and owned test windows; it is never an automatic fallback and overwrites the current clipboard without saving its previous contents. The packaged --smoke path uses temporary storage with capture disabled.

Encryption does not protect against same-user malware, administrators, system clipboard readers, destination applications, pagefiles or crash dumps. See the [threat model](docs/security/threat-model.md).
