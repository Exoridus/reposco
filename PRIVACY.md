# Privacy

Reposco stores history locally and has no telemetry, account, sync, updater or crash-upload service. Reposco-owned code makes no network requests. HTML/Markdown previews render bounded local text into images; standalone captured images and bounded table grids are also available. No external, local-file, UNC or embedded markup resources are loaded. Copied URLs are never fetched.

First launch starts paused. Start / resume clipboard capture is explicit consent to collect future supported text, markup and image changes. The capture setting persists across launches, including Pause. Neither launch nor Resume imports the already-present clipboard. Pause rejects pending captures. A privacy-rule change pauses capture, invalidates queued generations and remains pending until the storage worker has drained earlier operations and durably saved the new policy. Admission is rechecked before a capture transaction commits; obsolete writes roll back original data, dedup changes and eviction together. A COMMIT already admitted can finish before the asynchronous policy acknowledgement, never after the new policy is confirmed effective. Earlier stored entries are not retroactively deleted. Capture filters never change or clear the clipboard. Explicit replay replaces it with the selected stored supported representations; Ctrl+Enter copies only, while Enter/Shift+Enter request paste into the previous eligible application.

On launch Reposco creates or opens history.db and a versioned user-scope DPAPI key envelope, key.dat, under its Windows per-user application data location, even while capture is paused. A separate settings.ini stores capture/filter/retention preferences and native application exclusion paths, not clipboard contents. Database original representations, comparison text and summaries stay in SQLCipher. Keys are randomly generated and transient key buffers are wiped. Key loss may make history unrecoverable; no recovery/export feature exists.

Known exclusion/ignore markers and local-history opt-out are screened before payload access. Cloud-sync opt-out alone does not exclude local history. Native executable-path exclusions and default-on exact six-digit code exclusion are available. Optional exact eight-digit exclusion is off by default. Browser-extension provenance and arbitrary unmarked passwords cannot reliably be recognized. Do not enable capture while copying unmarked secrets. History uses 1000-item, 90-day and 1-GiB original payload limits. Canonical comparison text, metadata, encryption overhead and unused pages are additional disk usage; the physical database may remain larger after eviction. Confirmed Clear history in Settings/Tray pauses capture and deletes history logically, without promising forensic SSD erasure. Changing filters does not retroactively delete stored content.

Tests use synthetic data and temporary directories. Default tests never actively read or write the session clipboard; optional active native tests require a separate private window station and fail when isolation is unavailable. A separate explicitly coordinated interactive test mode uses only synthetic values and owned test windows; it is never an automatic fallback and overwrites the current clipboard without saving its previous contents. The packaged --smoke path uses temporary storage with capture disabled.

Encryption does not protect against same-user malware, administrators, system clipboard readers, destination applications, pagefiles or crash dumps. See the [threat model](docs/security/threat-model.md).
